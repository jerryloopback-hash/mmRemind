# mmRemind · 数学建模协作约束提醒 Skill

数学建模协作场景下的 agent 行为约束集：当用户调用 agent 开展**任何与数学建模相关的任务**——赛题分析、文献检索、方法对比与决策、模型方案设计、模型求解与代码实现、论文撰写等——时，提醒 agent 遵循四条协作准则。兼容 ZCode / Claude Code 的 skill 格式，可移植到任何支持「指令文件自动触发」机制的 agent。

核心立场：**agent 是数学建模任务的探索协助者，不是"无论如何把结果跑出来"的执行者。** 数学建模的关键在于探索——探索题意、探索可行方法、探索最优模型、探索最高质量/最高效率的解法、探索易懂且体现创新点的写作结构。四条准则全部服务于这一立场。

## 一、文件结构（本仓库根目录 = skill 根目录）

```
mmRemind/                       # 仓库根，移植时整个目录放入 agent 的 skills 目录
├── SKILL.md                    # 唯一运行时文件：frontmatter + 四条协作准则（约 55 行）
└── README.md                   # 本文件（使用/转移/移植说明，不属于 skill 运行时）
```

## 二、Skill 逻辑（供移植者快速理解）

**1. 入口契约**：`SKILL.md` 开头是 YAML frontmatter——

```yaml
---
name: mmRemind
description: <触发描述：凡用户调用 Agent 开展任何与数学建模相关的任务时必须使用，无论任务大小>
---
```

- `name` 必须与所在文件夹名一致（`mmRemind`）。
- `description` 是 agent 决定是否触发本 skill 的唯一依据，刻意写得偏主动（"无论任务大小，只要识别出是数学建模场景就应加载"），移植时**原样保留**，映射到目标平台的等价字段即可。

**2. 加载模型**：单文件 skill，无按需分册、无脚本依赖。触发即整载（约 55 行），不拖累上下文。

**3. 四条协作准则**（SKILL.md 内有完整定义与强语气强调）：

| # | 准则 | 一句话要点 |
|---|---|---|
| 1 | 确认任务边界 | 先理解用户希望本任务探索和负责的范围；相邻问题再相通也不"顺便"越界分析（如第一问结论与第三问板块相通，不得顺手对第三问做分析和简单计算） |
| 2 | "探索"而非"执行" | 定位是探索协助者：以用户思路为核心陪跑发散，尤其在方法选择与建模框架规划上，不先入为主按自己"工程上高效"的思路带节奏 |
| 3 | 以用户决策为核心 | 方案确定后完全采纳用户思路；agent 的想法只在方案设计与提出阶段供参考，不反复提示，更不允许在实现代码时偷改回自己的原始偏好 |
| 4 | 鼓励提问和中断报告 | 遇到未预料的困难不自行改方案绕过；问题大、需大幅调整方案时**停止当前任务并立即汇报**，探索解决路径交由用户决策 |

**4. 立场依据**（SKILL.md 内明文写入）：用户才是数学建模比赛的实际参赛者，比 agent 更有赛题经验、更了解 agent 接触不到的约束（硬件、时间、文章想突出的重点、数据情况等），数学建模必然存在妥协。用户委托的真实意图不只是完成方案，更是**验证方案的优秀性以写进论文**。

> 大忌："用户拟定了初始方案并执行，于是我遇到各种问题都自行尝试修改方案以绕过，最终使得用户需要的结果被得出或近似得出。"

## 三、使用

### ZCode

```bash
# 本仓库克隆后，将整个目录复制到用户级 skills 目录（目录名必须是 mmRemind）
git clone https://github.com/jerryloopback-hash/mmRemind.git
mkdir -p ~/.zcode/skills
cp -r mmRemind ~/.zcode/skills/
```

重启会话后自动被发现。验证：新开会话给出一条数学建模任务（如「帮我分析第一问该用什么模型」），若 agent 先确认任务边界、以探索口吻讨论可选方法而非直接抛出"最优方案"，即触发成功。

## 四、移植到其他 Agent（改造指引）

本 skill 只依赖一个通用机制：**指令文件的自动发现与触发**（frontmatter 的 `name` + `description`）。无子文件、无脚本、无 shell 依赖，任何具备等价触发机制的平台都可承载。

**移植步骤**：① 建目录 `<skills目录>/mmRemind/`，放入 `SKILL.md`（README.md 可不放）；② 按平台要求映射 frontmatter 字段名（Claude Code 同样使用 `name`/`description`，通常零改动）；③ 四条准则的行为条款**原文不动**——强语气（感叹号、加粗、"大忌"引用块）是刻意的，弱化会降低遵守率；④ 用一条真实数模任务验证触发与行为。

## 五、设计说明

- 约束集由用户（数学建模参赛者）自撰并定稿（2026-09-06），针对 agent 在数模协作中的两类高频翻车：先入为主替换用户思路、遇到问题自行绕过导致方案失去验证价值。
- 结构化改写保留全部四条主旨、示例与红线，删减的只是口语化重复；后续扩充时注意保持单文件体量（目标 <100 行）。
- 与 [deAiWriting](https://github.com/jerryloopback-hash/deAiWriting)（同作者）配套使用：本 skill 约束建模协作行为，deAiWriting 约束论文写作文风。

## 六、边界与许可

- 仅面向数学建模协作场景；不包含建模方法、代码工具链或论文模板。
- 本 skill 约束 agent 的行为方式，**不替代用户决策**；准则本身即要求关键决策交还用户。
- 纯指令文件，无外部代码依赖与许可牵连。
